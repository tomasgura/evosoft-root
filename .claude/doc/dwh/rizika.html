Detail rizik

1. RabbitMQ autoCreate: true Vysoká

Popis: autoCreate: true způsobuje TCP spojení s RabbitMQ při každém HTTP requestu — i tam, kde frontu vůbec nepotřebuje.

Dopad: Výpadek RabbitMQ = 500 error na všech stránkách aplikace.

Řešení:

  1. Změnit autoCreate: false v config/rabbitmq.neon
  2. Fronty deklarovat jednorázově přes rabbitmq:declareQueuesAndExchanges
  3. Přidat health check endpoint pro RabbitMQ

8. Chybějící automatizované testy Vysoká

Popis: ETL pipeline, consumers a services nejsou pokryty integračními testy.

Dopad: Regrese v ETL logice nejsou automaticky detekovány.

Řešení: Přidat integrační testy pro: DataSourceService, ValidationService, PublicationService, RabbitMQ consumer flow.

10. Hyperdrive DROP procedura Vysoká

Popis: resources/hyperdrive/procedure/drop-postgre.sql obsahuje DROP SCHEMA CASCADE. Dostupná jako příkaz hyperdrive:procedure dropPostgre.

Dopad: Nechtěné spuštění = ztráta všech dat.

Řešení: Přidat --force flag, env check (blokovat na produkci), omezit přístup.

3. Chybějící Dead Letter Queue Střední

Popis: Trvale selhávající zpráva se requeue bez limitu pokusů → consumer se zacyklí.

Řešení: Nakonfigurovat DLQ pro každou frontu, přidat x-max-retries.

6. Šifrovací klíče v config souboru Střední

Popis: AES klíče (iv + secret) pro šifrování hesel zdrojových DB jsou v textovém souboru config/local.neon.

Dopad: Kompromitace serveru = kompromitace všech zdrojových DB hesel.

Řešení: Přesunout klíče do environment proměnných nebo HashiCorp Vault.

7. Výkon dataset_values (EAV) Střední

Popis: EAV struktura: pro každý záznam je N řádků (N = počet sloupců). Miliony entit = desítky milionů řádků.

Řešení: Indexy na (entity_id, def_id), pravidelný VACUUM/ANALYZE.

5. Kafka bez autentizace Střední

Popis: Kafka brokeři nemají nastavenou autentizaci (SASL/SSL) ve výchozím nastavení.

Řešení: Nakonfigurovat SASL autentizaci na produkci.

9. Tmp soubory Nízká

Popis: www/send_to_file/ a www/temp_files/ se automaticky nemaže.

Řešení: Cron job pro mazání starých souborů.
